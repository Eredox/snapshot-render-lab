## 3. Exploitability evidence vs advisory severity (SEC-002)
- *Advisory severity:* CRITICAL (CVSS 9.3) for unauthenticated reflected XSS through TanStack **server-function** responses.
- *Application exposure (pre- and post-fix):* the source defines **no `createServerFn`**; the only server handlers are `/sitemap.xml` and `/api/forms`. `GET /_serverFn/<anything>` returned **403** on the live site (audit) and on the local build. The origin sets no cookies and has no session. Exploitability before the fix was therefore LIKELY nil; the upgrade removes the latent risk should server functions ever be added.
- *Artifact:* patched code is present in the build output (marker above).

`security-headers.test.ts`, `forms-hardening.test.ts`, `booking-privacy.test.ts`, `seo-metadata.test.ts` (security.txt), updated `launch-invariants.test.ts`; plus `scripts/verify-release.mjs` (HTTP, header, 404, link, external-destination and browser checks).

## 5. Residual risks
- No live verification (headers, rate limits, TLS) — by instruction.
- Without CAPTCHA, a distributed low-rate attacker can still submit up to the per-client/global limits (120/hour overall) — bounded, but non-zero CRM/e-mail noise.
- Rate-limit state is per process (single container assumed) and resets on restart.
- CSP keeps `style-src-attr 'unsafe-inline'` (React style attributes cannot run script); remove only if all inline styles are eliminated.
- The Docker image build, `nginx -t`, and Playwright suites were not run.
